# WoW Forever talent calculator

Static site hosted on GitHub Pages (`seos-a/forever-info`, branch `main`).
The live page is `index.html` in the repo root. It is a generated, self-contained
file (~830 KB): do not hand-edit it. Make changes in `tc/` and rebuild.

## Layout

- `index.html`: the published site (build output, copied here by hand)
- `<section>.html` (`rogue.html`, `legacy.html`, `spellbook.html`, `changes.html`, `raid.html`...): the same page once per section, so each
  has its own address (`foreverinfo.io/rogue`; GitHub Pages serves `rogue.html` for it). Build output too, copied with `index.html`
- `images/`: icons, talent-tree backgrounds and NPC model thumbnails, served
  next to `index.html` (`images/icons/`, `images/backgrounds/`, `images/models/`)
- `tc/`: the source folder
  - `template2.html`: page layout, styling and behavior (this is what the live site uses)
  - `template.html`: an older layout; still built, but not published
  - `build.py`: the build script
  - `ranks.py`, `spellbook.py`, `raidcomp.py`: helpers imported by `build.py`
  - Data:
    - `<class>.json` (druid, hunter, mage, paladin, priest, rogue, shaman, warlock, warrior): talent trees
    - `legacy_raw.json`: the account-wide Legacy tree (kept current by `sync_legacy.py`)
    - `racials.json`: racials (traits and Priest racial spells, worded for the site; kept current by `sync_racials.py`)
    - `spells_raw.json`, `ranks_raw.json`, `rank_tips.json`: spellbook (`rank_tips.json` holds each rank's cost / range / cast time / cooldown, a single-rank spell's as rank 1)
    - `assets.json`: icon and spec lists used to write `image-list.txt`
    - `talent_meta.json`: cost / range / cast time / cooldown rows per rank for active
      talents, shown in talent tooltips. Generated by `talent_meta.py`, which pulls
      Wowhead's WoW Forever talent feed and spell tooltips. Re-run `py talent_meta.py`
      (needs internet) when talents change; `build.py` flags any name that no longer matches.
    - `raidcomp.json`: the Raid Composition page (`/raid`): buff / debuff / other categories with each one's stacking note
      (`status` "confirmed" from a Forever tooltip or patch note, "assumed" = Classic's rule), the utility / cooldown / crowd
      control lists, which buffs reach only the caster's group (`party`), and `extra` for pet abilities, renamed spells and
      text newer than the spellbook's. Spells are named as in the spellbook or a talent tree; `raidcomp.py` works out each
      one's class, icon, text and specs (a talent: its tree; a trainer spell: all three) and `build.py` prints
      `raid comp problems: [...]` (should be `[]`) for a name that no longer matches. The page's link is one character
      per raid slot (`/raid?036-9ce`: spec index 0-9a-q in class order, `r` for Feral (Cat) (Feral is split into Bear and Cat buttons; `1` is Bear), `-` empty),
      then optionally `~` and the player names typed over the slots, comma-separated in slot order, spaces as `_` (`/raid?036~Bob,,Ann_Lee`)
  - Beta sync scripts (run from `tc/`, need internet):
    - `sync_talents.py`: updates the `<class>.json` files from Wowhead's WoW Forever talent feed
      (position, ranks, icon, prerequisite and each rank's full text, stored as a 9th field
      that `build.py` shows as-is)
    - `sync_spells.py`: updates the spellbook (`spells_raw.json`, `ranks_raw.json`,
      `rank_tips.json`) from each rank's tooltip. The spellbook holds what the beta's class trainers teach (Wowhead's
      talent feed). A spell a trainer now teaches that the spellbook lacks is added when Wowhead's spellbook change page
      gives its tab (a Classic spell); a brand-new Forever spell has no tab there (tab 0), so it is listed under "To check
      by hand" to be placed by hand, as are rank-count and level changes of spells already in the spellbook. Wowhead's
      spellbook pages also list spells Forever removed (Detect Magic, Curse of Shadow...): those are rightly left out
    - `sync_racials.py` (after `changelog.py`): compares each racial trait's Wowhead tooltip (spell ids in `TRAIT_IDS`)
      with the copy saved last run in `racials_wh.json`. A trait the site shows exactly as Wowhead words it is updated in
      `racials.json` automatically; one worded by hand (Eureka! and Expansive Mind merge their per-class versions, Touch of
      the Grave its two proc chances; Touch of Weakness and Hex of Weakness fix
      Wowhead's typos) is never overwritten but listed under "Racials: needs a look" in the pull request. Racial changes are
      summarised in the pull request report only, not on the Class Changes page (the developers don't plan to change
      racials after launch). It also reads Wowhead's race pages and lists any racial added or removed there. Priest racial spells
      follow the spellbook text (`spells_raw.json`)
    - `sync_legacy.py`: rewrites `legacy_raw.json` from Wowhead's Legacy Calculator data feed (nodes, ranks, rank texts,
      points needed, cast time / cooldown, the arrows between nodes; positions are Wowhead's grid of 750 units a slot,
      stored as 14 + slot * 92) and lists what changed. The feed doesn't say how many points an arrow needs, so existing
      links keep the site's number (1; Reagent Economy 2) and a new link gets 1 and is listed to check
    - `fetch_images.py`: after a build, downloads any icon in `web/image-list.txt` the repo lacks
    - `changelog.py`: when Wowhead has a new beta build, adds its talent and spell changes per class to
      `changes.json` (shown on the Class Changes page, one entry per build, with a picker for older ones). It reads
      Wowhead's WoW Forever change pages (`wowhead.com/forever/changes/talents/<class>?vs=<build>` and
      `.../spellbook/...`), which hold every build's tooltips, and marks each change a buff, nerf or other change as a
      best guess from the numbers. It also keeps `version.json` (beta version, build and the date it appeared, shown
      bottom left like WoW's login screen) in step with Blizzard's patch server. `--dry` previews;
      `--rebuild --date=YYYY-MM-DD` rebuilds the whole history (the date is the latest build's, which Wowhead doesn't list).
      Its "Needs a look" scan flags changes that look like data errors (a number changing 3x or more, every rank suddenly
      showing the same number, values becoming 0, leftover formulas, removals); the daily job puts that list at the top
      of the pull request. Wowhead's data is sometimes wrong (Thick Hide, Oct 8: 180 armor per level at every rank, in
      game 1 / 2 / 3): once checked in game, a wrong Class Changes entry is corrected in `changes_fixes.json` (applied on
      every run, so rebuilds keep it) and a wrong talent text in `TEXT_FIXES` in `build.py`
  - `experiment.py` + `experiment/`: the Experiment page (`/experiment`, linked faintly bottom right on every page): DPS /
    Healing / Tanks race sims. `experiment/` is the only source: the page (`page.html`), its scripts and its datasets
    (`data/<id>.json`); edit them there and rebuild. `experiment.py` stands in for the dashboard runtime the page was first
    written for and `build.py` writes `web/experiment.html` (not indexed). The page began as the "Forever Race/Spec
    Comparison" dashboard artifact (https://claude.ai/artifact/KhLhWEBf6f1ceiUyotPXUB), which is now an archive (last
    synced Oct 28, 2026, before the build renames): don't update it or copy from it
  - `bg.jpg`: page background, embedded as base64 (`bg.orig.jpg` and `bg_source.png` are originals)
  - `art/`: logo/banner, fonts, cursors and favicon source files. `build.py` does
    not read these; they are already inlined in `template2.html` as data URIs.
    To change one, re-encode it and replace the data URI in the template. `art/skyborne_icon.py` makes the zoomed Horde Skyborne
    portrait (`images/icons/race_skyborne_male.jpg`); `art/bloodelf_icon.py` the Alliance one. Phones show the logo without the BETA!
    sticker instead, from files: `images/logo-nobeta.png` and `images/logo-hallow-nobeta.png` (copies of
    `art/banner_title_nobeta.png` and `art/banner_hallow_nobeta.png`; the Hallow's End one is made by
    `HALLOW_SRC=art/banner_title_nobeta.png HALLOW_OUT=art/banner_hallow_nobeta.png py art/hallow_logo.py`).

## How the build works

`build.py` must be run from inside `tc/` (it uses relative paths):

1. Loads the class JSON files, fixes Wowhead placeholder values (`fix_desc`),
   applies the hand `OVERRIDES`, and works out per-rank values (`ranks.per_rank`).
   It prints `problems: [...]`. This should be `[]`.
2. Builds the Legacy tree and the spellbook (`spellbook.build()`).
3. Replaces the placeholders `/*DATA*/`, `/*BG*/`, `/*RACIALS*/` and `/*SPELLBOOK*/` in each template and writes:
   - `../Forever-Talents.html` (from `template.html`)
   - `../Forever-Talents-Classic-Style.html` (from `template2.html`)
4. Turns the Classic-Style page into the web version: Wowhead image URLs
   (`wow.zamimg.com`) become local `images/...` paths, and the GoatCounter
   analytics snippet is added before `</head>`, along with the icon links and the link-preview (Open Graph) tags,
   which point at `https://foreverinfo.io/`. The preview picture `images/og.png` is made by `tc/art/og_image.py`;
   `favicon.png`, `favicon.ico`, the larger icons (`apple-touch-icon.png` for iPhone bookmarks, `favicon-48.png` / `favicon-96.png` for Google results, `icon-192.png` / `icon-512.png` for Android; all made by `tc/art/touch_icon.py`; the browser-tab icons (`favicon.png`, `favicon.ico`) are transparent behind the murloc, the rest sit on black, since home screens and Google fill transparency with white; after changing them, bump `ICONV` in `build.py` so browsers fetch the new files), `site.webmanifest` (Android home screen), `404.html` (GitHub Pages shows it for any address that doesn't exist; `build.py` writes it from `tc/page404.html` with the main page's parchment textures, styled after the Burning Crusade-era WoW site's 404 page), `robots.txt` and `sitemap.xml` sit in the repo root. The head also gets a WebSite structured-data tag naming the site "Forever Info" for Google results. It asserts that no `zamimg` URLs
   remain, then writes:
   - `../web/index.html`: the site
   - `../web/<section>.html`: the same page for each class, `legacy`, `racials`, `spellbook`, `changes` and `raid`, with its own
     title, description and link-preview tags
   - `../web/image-list.txt`: `url|local path` lines for every image the site needs

Because `tc/..` is the repo root, all of these outputs land in the repo root
(`Forever-Talents*.html`, `web/`). `.gitignore` excludes them; only `index.html`
is published.

All text files are read and written as UTF-8 with LF line endings, so the output
is the same on every OS.

## Rebuilding the site

On this Windows machine, Python is `py` (`python`/`python3` are Store stubs).
Elsewhere use `python3`.

```bash
cd tc
py build.py
cp ../web/*.html ..
```

Check with `git diff --stat`: normally only the published pages (`index.html` and the section pages) and the source files you
edited should change. If you add talents or spells with new icons, check
`web/image-list.txt` and add any missing images under `images/`.

Sanity check: rebuilding the current, unchanged sources reproduces the committed
`index.html` byte for byte.

## Page addresses

On the website every page has its own address: `/rogue`, a build as `/rogue?05-0-55002`, `/racials?nightelf`,
`/spellbook?rogue` (one spellbook per class, no race: older `?rogue:human` links drop the race), `/changes?rogue:70291` (`linkFor` / `curLink` / `setLink` in `template2.html`; inside the page
each address is still one "link" string such as `rogue:05-0-55002`). Old `#rogue:05-0-55002` links still open and are
moved to the new address; the offline `Forever-Talents*.html` files keep the `#` form. `404.html` sends section addresses
with a slash after them (`/rogue/`, `/spellbook/rogue/human`) to the right page. GoatCounter counts each page by its
address (`/rogue`; home is `/`).

## Committing

Commit and push straight to `main`. GitHub Pages deploys from there.

## IndexNow (Bing)

`.github/workflows/indexnow.yml` runs after every push to `main` that changes `index.html` (including merged sync pull
requests): once GitHub Pages has published, it tells IndexNow (Bing, Yandex...) that https://foreverinfo.io/ changed. It
needs the IndexNow key file in the repo root, `<32 hex characters>.txt` containing that same key (public on purpose);
without it the workflow does nothing.

## Raid link previews (Cloudflare Worker)

`worker/` is a Cloudflare Worker on `foreverinfo.io/raid*` only: it gives a shared raid link a picture of its roster
(`/raid-preview.png?<code>`, drawn by `worker/src/roster.js`) in the page's link-preview tags, and makes the page's
Copy Link short links (`/raid/<id>`, rosters kept in Cloudflare KV; anywhere else Copy Link copies the long link). `worker/src/specs.js`
copies the page's specs (link-code order, icons, class colours) from `tc/template2.html`: change both together.
`.github/workflows/raid-preview.yml` tests it on every push to `worker/` and deploys from `main` once the
`CLOUDFLARE_API_TOKEN` / `CLOUDFLARE_ACCOUNT_ID` secrets exist. Setup (moving DNS to Cloudflare) is in `worker/README.md`.

## Automatic beta sync

`.github/workflows/beta-sync.yml` runs twice a day, 10:00 PM and 10:30 AM US Eastern (and on demand from the Actions tab): it runs the
sync scripts, `talent_meta.py`, the build and `fetch_images.py`, and if anything changed opens a
pull request on the `beta-sync` branch with a report of what changed. Merging it publishes the
update. The repo setting "Allow GitHub Actions to create and approve pull requests" must be on.
